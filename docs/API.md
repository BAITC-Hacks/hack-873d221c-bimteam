# Договорённость между сервером и интерфейсом

Сервер и страница работают по одному адресу. Рустем открывает `/`, не сам HTML-файл двойным кликом. Все пути в `fetch` относительные. При переходе на отдельный frontend-сервер вместе настройте CORS или прокси.

`GET /api/options` возвращает `cities`, `categories`, `event_formats`, `languages` — списки строк на русском; `date_min`, `date_max` — границы календаря. Берите значения формы отсюда.

`POST /api/recommend`, тело в формате JSON:

```json
{"city":"Алматы","category":"Ведущий","event_format":"корпоратив","date":"2026-10-10","budget":1000000,"duration_hours":null,"language":null}
```

`duration_hours` и `language` можно опустить или передать `null`. Бюджет — целое число тенге за мероприятие. Дата — `YYYY-MM-DD` в пределах известного календаря. Категории и форматы передаются по-русски как в `/api/options`.

Ответ HTTP 200 содержит:

| Поле | Значение |
| --- | --- |
| `status` | `ok`, `no_category_in_city` или `no_matches` |
| `message` | Готовое русское объяснение результата |
| `results` | От 0 до 3 карточек |
| `candidate_count` | Сколько профилей нужной категории в городе до остальных условий |
| `eligible_count` | Сколько прошло все условия до ограничения в три карточки |
| `rejection_summary` | Счётчики причин `busy`, `budget`, `format`, `duration`, `language`; возможны пересечения |

Карточка: `id`, `name`, `category`, `city`, `price_from_kzt` (число), `explanation` (проверенные факты), `profile_excerpt` (точный фрагмент описания), `synthetic`, `city_imputed`, `price_imputed` (логические значения). Поле `explanation_source` равно `rules` или `nvidia_quote`; служит для диагностики, его не обязательно показывать пользователю. Цитату выводите отдельно с подписью «Из профиля».

HTTP 422 означает ошибку ввода: ответ содержит `message` по-русски и `fields` со списком ошибочных полей. Сетевые ошибки и HTTP 5xx отображайте отдельно от нормального пустого результата. Схема входного запроса доступна в `/openapi.json`, пробные запросы — в `/docs`. Формат ответа пока описан здесь; отдельная машинная схема ответа ещё не добавлена.

При нуле карточек показывайте `message`, при одной или двух — карточки плюс `message`. Не дополняйте список вымышленными профилями. Состояние ожидания обязательно; после ошибки кнопку можно нажать повторно.

## Обзор площадок для сравнения цен

`GET /api/venues?city=Алматы` — все площадки города, по возрастанию `price_from_kzt`, затем `id`. Без `city` возвращает площадки всех городов. Ответ: `{venues: [...], availability_checked: false}`. В отличие от подбора, обзор не ограничен тремя и не фильтруется по дате, бюджету, формату, языку или длительности; интерфейс должен явно обозначать это и не обещать доступность.

Элемент: `id`, `name` (дословное название перед тире в описании, иначе имя профиля), `profile_name` (исходное анонимное имя), `category`, `categories`, `city`, `price_from_kzt`, `description`, `price_imputed`, `city_imputed`, `synthetic`. Координат в ответе нет. Демонстрационная география отдельно описана в `VENUE_MAP.md`.

У карточек площадок в `/api/recommend` добавлено необязательное `venue_name` для отображения названия. Поле `name` и все ограничения подбора сохранены. Для заголовка можно использовать `venue_name || name`.
