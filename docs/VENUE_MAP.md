# Карта площадок

Карта включается для банкетных залов, ресторанов, отелей и загородных площадок. Быстрый пример «Площадки на карте»: Алматы, свадьба, 10.10.2026, бюджет 6 000 000 ₸, без ограничения языка и длительности. В этом примере есть три результата. Кнопка явно задаёт пример, обычный подбор не меняет условия пользователя.

В обычном подборе метки представляют **только показанные результаты `/api/recommend` (до трёх)**. Цены «от» берутся из того же ответа, что и карточки; карта не меняет сортировку. При изменении условий старые точки удаляются до следующего подбора.

Отдельная кнопка «Все площадки города и цены на карте» открывает обзор `/api/venues?city=…`: весь каталог площадок города, по цене и ID, без ограничения тремя и без фильтрации по бюджету/дате. Эти условия явно указаны над картой; обзор не обещает доступность и не обозначает площадки как подходящие. Форма сохраняет значения. В Алматы семь площадок, в Астане одна. Возврат к проверке — кнопкой «Проверить по моим условиям» или обычным подбором.

На метках видны **название из описания и цена**. Имена анонимных профилей и ID сохранены в карточках. Названия не восстанавливаются через внешние сервисы. `/api/recommend` сохраняет поле `name` и дополнительно отдаёт `venue_name` для площадок. Если в описании нет явного названия перед тире, используется имя профиля. Цены никогда не извлекаются из текста и не копируются в геоданные: оба API используют исходный CSV. Подписи на карте раздвигаются при наложении и соединяются тонкой линией с исходной точкой; координаты этим не меняются.

## Демо и реальные адреса

В исходном каталоге нет адресов/координат. Присланный `hackathon dataset preview.html` содержит те же 66 ID и тоже не содержит адресов/координат. По согласованию с пользователем восемь площадок получили **условные демонстрационные точки** в `web/data/venue-locations.json`. Это не геокодирование и не подтверждение расположения. На карте есть постоянная заметная подпись, в метках (доступные названия), всплывающих карточках и ссылках из списка — обозначение демо. Перехода к маршруту для таких точек нет.

Чтобы подключить реальные публичные адреса, замените запись по существующему ID:

```json
{"city":"Алматы","lat":43.24,"lng":76.92,"kind":"verified","address":"ЗДЕСЬ НУЖЕН ПРОВЕРЕННЫЙ АДРЕС"}
```

Числа в примере — только пример формата, их тоже нужно заменить проверенными координатами. Для `verified` обязателен непустой адрес. Город записи должен совпадать с городом результата. Неполные/некорректные координаты отбрасываются: центр города никогда не подставляется вместо адреса. Обзор города при отсутствии меток не означает расположение площадки. `map-data.mjs` содержит проверку и объединение данных, API менять не нужно.

## Интерфейс и зависимости

- Список / карта со списком рядом; на мобильном карта выше карточек.
- Метки с ценами, карточка по нажатию, переход к полному описанию, выделение соответствующего результата.
- Масштаб, все точки в кадре, развёрнутая карта в модальном окне; Escape и возврат фокуса.
- Клавиатура: Tab к меткам, Enter/пробел открывают карточку; стрелки и +/− работают в карте. Масштаб колёсиком выключен, чтобы не мешать прокрутке страницы.
- Светлая и ночная темы, reduced motion. Загрузка библиотеки и точек отложена до открытия карты; ошибки не препятствуют обычному подбору, есть повтор.

Локально закреплена [Leaflet 1.9.4](https://leafletjs.com/download.html); JS/CSS проверены по SHA256 официальной документации. Лицензия: `web/vendor/leaflet/LICENSE`. Используются только DivIcon и собственные кнопки, стандартные растровые маркеры и иконки слоёв не нужны.

Подложка — [OpenStreetMap](https://www.openstreetmap.org/copyright), запросы выполняет браузер только для видимой карты. [Политика тайлов](https://operations.osmfoundation.org/policies/tiles/): видимая атрибуция, обычный браузерный кэш, без прокси, предзагрузки города и офлайн-выгрузки. Фон требует интернета. API-ключ не нужен. Для большого публичного трафика выберите отдельного поставщика тайлов; адрес подложки находится в `venue-map.js`.

## Проверка

`node --test tests/map-data.test.mjs` проверяет, что карта не добавляет исключённые профили, сохраняет цены/порядок API, не выдаёт демо за проверенные адреса и отбрасывает непригодные координаты. `pytest` проверяет существующий подбор.
