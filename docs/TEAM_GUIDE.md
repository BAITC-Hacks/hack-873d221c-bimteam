# Как работать вдвоём

Абзал делает бэкенд: сервер читает данные, проверяет условия, выбирает подрядчиков и возвращает результат. Рустем делает фронтенд: страницу с формой и карточками. Стек — FastAPI и обычные HTML, CSS, JavaScript; npm для интерфейса не нужен.

## Кто за что отвечает

| Участник | Свои папки | Результат |
| --- | --- | --- |
| Абзал | `app/`, `api/`, `scripts/`, `tests/` | API, чтение данных, фильтрация, оценка, объяснения, проверки |
| Рустем | `web/` | Форма, запрос к серверу, карточки, состояния загрузки и ошибок |
| Вместе | `README.md`, `docs/` | Описание запуска, договорённости между частями, сценарии демо |

Перед изменением общей документации договоритесь, кто сейчас её редактирует. Если нужно поменять поля API, сначала сообщите друг другу: переименование поля на сервере может сломать страницу.

## Термины без сложности

- **Репозиторий** — папка проекта с историей изменений. Копия на GitHub помогает обмениваться работой.
- **Ветка** — отдельная линия изменений. `main` хранит общую рабочую версию; каждый делает задачу в своей ветке.
- **Commit** — сохранённая порция изменений с подписью. Она пока находится только на вашем компьютере.
- **Push** — отправка сохранённых изменений на GitHub.
- **Pull** — получение изменений с GitHub на свой компьютер.
- **PR (pull request)** — предложение добавить вашу ветку в `main`. На сайте видно, какие строки изменятся.
- **Merge** — принятие PR: изменения становятся частью `main`.

## Первый запуск Git на своём компьютере

Если папки проекта ещё нет, откройте терминал в месте, где хотите её создать:

```powershell
git clone https://github.com/BAITC-Hacks/hack-873d221c-bimteam.git
cd hack-873d221c-bimteam
```

Если папка уже есть, откройте терминал внутри неё. Повторно клонировать проект туда же не нужно. Доступ к закрытому репозиторию должен быть выдан вашему аккаунту GitHub.

Перед началом задачи проверьте состояние:

```powershell
git status
git switch main
git pull --ff-only
```

Начинайте новую ветку с чистым состоянием: если `git status` показывает незавершённые изменения, сначала завершите и сохраните текущую работу в её ветке. Если Git сообщает об ошибке, не продолжайте команды вслепую и не удаляйте файлы для её устранения.

Абзал создаёт свою ветку:

```powershell
git switch -c abzal/backend
```

Рустем создаёт свою:

```powershell
git switch -c rustem/frontend
```

`-c` создаёт ветку один раз. Чтобы вернуться к уже существующей, используйте `git switch abzal/backend` или `git switch rustem/frontend` без `-c`.

## Как отправить готовую часть

Сначала проверьте приложение по инструкции в README. Абзал также запускает `pytest`. Затем посмотрите свои изменения:

```powershell
git status
git diff
```

Абзал добавляет свои папки и сохраняет изменения:

```powershell
git add app/ api/ scripts/ tests/
git diff --cached
git commit -m "Добавить подбор подрядчиков по условиям"
git push -u origin HEAD
```

Рустем делает то же для интерфейса:

```powershell
git add web/
git diff --cached
git commit -m "Добавить форму и карточки подрядчиков"
git push -u origin HEAD
```

`git diff --cached` показывает именно то, что попадёт в commit. Проверьте, что там только нужные изменения и нет ключей. В подписи commit коротко напишите, что сделали. `HEAD` здесь означает текущую ветку.

Если меняли согласованную документацию, добавляйте конкретный файл отдельной командой, например `git add docs/TEAM_GUIDE.md`. Не используйте без проверки `git add .`: он может захватить лишние файлы.

## Как объединить работу через GitHub

1. Откройте [репозиторий команды](https://github.com/BAITC-Hacks/hack-873d221c-bimteam).
2. Нажмите **Compare & pull request** для отправленной ветки. Если кнопки нет: **Pull requests → New pull request**.
3. Выберите `base: main`, а в `compare` — свою ветку.
4. Напишите, что изменилось и как проверили. Нажмите **Create pull request**.
5. Тиммейт смотрит вкладку **Files changed** и проверяет, не сломалось ли соединение фронтенда с бэкендом.
6. Если всё работает и GitHub позволяет объединение, нажмите **Merge pull request**, затем подтвердите.

При сообщении о конфликте Git не может сам решить, какие изменения оставить. Покажите друг другу конфликтующие строки и согласуйте результат; не выбирайте удаление чужой работы наугад.

После принятия PR каждый обновляет свою локальную `main`:

```powershell
git switch main
git pull --ff-only
```

Если `--ff-only` завершился ошибкой, локальная история отличается от общей. Остановитесь и разберитесь вместе; не используйте `reset --hard` или принудительный push.

Следующую задачу начинайте в новой ветке от обновлённой `main`, например `abzal/explanations` или `rustem/empty-state`. Это помогает не смешивать уже принятую работу с новой.

## Как соединяются сервер и страница

- `GET /api/options` — Рустем получает значения для списков в форме: города, категории и другие доступные варианты.
- `POST /api/recommend` — страница отправляет условия и получает подходящих подрядчиков с объяснениями.
- `/docs` — FastAPI автоматически показывает описание API и позволяет отправить пробный запрос прямо из браузера. Здесь сверяйте точные названия и типы полей.

После запуска сервера по README откройте `http://127.0.0.1:8000/docs`. Команда запуска сервера — `uvicorn app.main:app --no-access-log`; зависимости и окружение предварительно подготовьте по README. Старый `api.main:app` тоже работает как совместимый вход.

Бэкенд отвечает за правильность результата даже при запросе без страницы. Фронтенд отображает полученный результат и помогает пользователю исправить ввод. Все сообщения для пользователя — на русском языке.

## План минимальной рабочей версии

Бэкенд по новому ТЗ реализован в `abzal/filters`. Чтобы посмотреть именно его, используйте команды из корневого README, а не устаревший список проверок внутри `web/README.md`. Перед объединением с `main` Рустем проверяет свою страницу с новым сервером. Новый API и legacy-форма поддерживаются одновременно; смешивать имена полей в одном запросе нельзя.

1. **Согласовать обмен данными.** Вместе отправить пробный запрос через `/docs`, проверить поля ответа. Рустем может строить карточки по этому примеру, пока Абзал дорабатывает алгоритм.
2. **Абзал: корректный подбор.** Подключить 66 профилей из исходных данных, проверить ограничения из ТЗ, исключать неподходящих до оценки. Одинаковый запрос должен давать одинаковый порядок. При равных баллах использовать стабильные дополнительные правила сортировки.
3. **Рустем: полный путь пользователя.** Сделать форму, кнопку подбора, индикатор ожидания, карточки и понятную ошибку запроса. Обработать отсутствие категории в городе, отсутствие подходящих по условиям и результат из одного или двух подрядчиков.
4. **Абзал: объяснения.** Для каждого результата дать конкретные причины из данных. Если подключается NVIDIA API, запросы идут с сервера. При недоступности модели подбор должен работать с объяснениями, собранными из проверенных фактов.
5. **Вместе: проверка и демо.** Проверить страницу с настоящим сервером, повторяемость выдачи и пустые результаты. Подготовить README: по ТЗ за него предусмотрено 25 баллов.

## Ключ NVIDIA и другие секреты

Секреты загружаются только из `.env`. Каждый создаёт этот файл локально по инструкции проекта. Ключ нельзя вставлять в `web/`, документацию, commit, скриншоты или отправлять в PR. `.env.example` содержит только названия настроек и безопасные примеры без действующих ключей. `.env` должен быть исключён через `.gitignore`.

Фронтенд обращается к вашему серверу, а сервер — к NVIDIA. Модель не должна возвращать занятого подрядчика, менять обязательные ограничения или придумывать свойства профиля.

## Что показать на защите

- Обычный запрос: подходящие карточки и индивидуальные объяснения.
- Редкую категорию: корректное отображение малого числа результатов.
- Запрос без результатов: понятное объяснение, что не подошло.
- Проверку занятости на дату: занятый подрядчик не появляется.
- Повтор того же запроса: порядок сохраняется.

До выступления запишите конкретные работающие запросы на ваших данных. В README укажите установку и запуск, роли участников, правила фильтрации и оценки, роль AI, ограничения решения и эти примеры. Абзал объясняет подбор и API, Рустем показывает путь пользователя на странице.
