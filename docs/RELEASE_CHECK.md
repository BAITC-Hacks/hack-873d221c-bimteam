## Чистая установка и воспроизводимость

В отдельную папку скачан чистый clone main из GitHub, затем он обновлён
fast-forward до проверяемого коммита. До установки в нём не было `.venv`,
`.env` и `cache/`; окружение из рабочей копии не копировалось.

Использованы Windows, Windows PowerShell 5.1, Python 3.12.14 и Node.js 24.19.0.
Путь установленного Python добавлен только в PATH процесса проверки;
системные настройки не менялись. Интернет требовался для pip, часть пакетов
взята из его обычного кэша загрузок.

Проверены команды:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Check
.\.venv\Scripts\python.exe -m pip check
$env:PYTEST_DEBUG_TEMPROOT = (New-Item -ItemType Directory -Force cache/pytest).FullName
.\.venv\Scripts\python.exe -m pytest -q
node --test tests/map-data.test.mjs
.\.venv\Scripts\python.exe scripts/find_demo_queries.py
git diff --exit-code -- data/demo_queries.json data/demo_requests
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001 --no-access-log
```

Установщик вывел «Установка готова, профилей: 66», pip не нашёл несовместимых
зависимостей. Генерация демо не изменила сохранённые файлы. Порт 8001 использован,
чтобы не мешать рабочему сайту на 8000; проверочный сервер затем остановлен.
Проверены синтаксис четырёх JS-файлов и `bash -n scripts/start.sh`.

Основные установленные версии: FastAPI 0.141.1, Uvicorn 0.53.0,
Pydantic 2.13.5, pydantic-settings 2.15.0, NumPy 2.5.3, OpenAI SDK 2.54.0,
httpx 0.28.1, python-dotenv 1.2.3, pytest 8.4.2, Starlette 1.7.0.
Тесты выдают одно предупреждение Starlette об устаревании httpx TestClient;
это не падение теста. Требования частично заданы диапазонами, не полным lock-файлом.
